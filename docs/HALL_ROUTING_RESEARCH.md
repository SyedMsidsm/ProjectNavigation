# Shared halls and route choice

The field example has a measured 1.4 m walk from an unnamed junction to a room followed by a 2.8 m reversal toward a washroom. Both segments share the first 1.4 m. Splitting the return at the earlier junction gives a three-way hall. The direct route is 11.9 m instead of 14.7 m on this recording. These are map distances estimated from steps. The original recording remains the source data. Normalization on load accepts a unique, collinear reversal with matching coordinates on the same floor. Two nearby points alone are insufficient evidence for a walkable connection. Ambiguous returns require the recorder to confirm an existing junction. For future work, compare proposed loop closures against labelled intersections before widening the matching tolerance. See the [Cartographer pose-graph configuration](https://google-cartographer.github.io/cartographer/configuration_files/pose_graph.html).

For a one-floor demo, shortest path minimizes recorded walking distance. Risk-aware planning adds a heuristic cost at each transition for turns, junction complexity, distance and sign readability. At a recognizable sign it also evaluates the cost and estimated benefit of asking for a scan. It models the chance of losing one's way, not physical safety. The existing two-route test floor gives 35 m for shortest and 40 m for risk-aware with lower modelled risk. A one-path hall should give the same route for both options. Test both types of floor during the demo. A research evaluation should record wrong turns and prompts per completed route under both policies before reporting a benefit.

Bundled ML Kit OCR works on the phone and the user can correct sign text before saving. Test glare, multiple lines, permission denial and adjacent signs. Gemma is suitable for indirect destination language. Common restroom requests use a constrained set of real saved facilities so a single known washroom can be suggested immediately and several can be offered as choices. Confirm every destination before starting. [ML Kit text recognition](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)

The map displays a schematic trail with doorway markers. Zoom and pan let users inspect crowded areas. Navigation can prioritize route labels at overview scale. Real room walls or 3D footprints require measured or imported geometry. ARCore uses visual features and motion sensors, so evaluate low texture and poor lighting before relying on it in the demo. SceneView could render a future surveyed model. Android exposes separate step and orientation sensors. Hardware events can be delayed. Switch to the software footfall detector only after confirmed cadence and sustained hardware silence, then ignore late hardware steps for that listening session. Test against counted walks and stationary handling. RoNIN is a useful research baseline for learned inertial odometry. Target-phone accuracy, latency and carry-mode comparisons would be necessary before substituting it for the current detector.
